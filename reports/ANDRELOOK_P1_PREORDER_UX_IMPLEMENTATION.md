# ANDRELOOK — P1: открытие формы предзаказа одним нажатием

Дата: 31.10.2026. Ветка: `codex/conversion-recovery-p0-p1`. P1 — отдельный коммит поверх P0; **ни staging, ни production не выпускались**.

## Изменение

- Кнопка товара и фиксированная мобильная кнопка теперь открывают существующую форму даже без выбранного размера. Выбранные до открытия цвет и размер сохраняются.
- При отсутствующем обязательном параметре P0-событие `preorder_selection_required` по-прежнему фиксирует пробел в выборе, но не блокирует форму. `preorder_open` означает фактическое открытие; повторное нажатие при уже открытой форме не создаёт новое событие.
- В форме размер либо явная опция помощи с размером остаётся обязательным. Цвет, если он есть у товара, также обязателен. Серверные schema/eligibility проверки, idempotency key, существующие способы получения и оплаты не ослаблены.
- Удалены только устаревшие сообщения и фокус-перенаправление, относившиеся к прежней блокировке до формы. Новый checkout, стили, цены, каталог, CRM и платёжная логика не добавлялись и не менялись.

## Проверки

- Локальная временная fixture-страница использовала реальные `ProductConfigurator`, `ProductInteractionProvider` и `RequestForm` с синтетическим товаром. Fixture удалена до финального build/коммита.
- Браузер: на 390 px кнопка открыла форму при пустом размере; нативное поле `size` было `required` и невалидным до выбора. После выбора `M`, ввода имени, закрытия и повторного открытия оба значения сохранились.
- Браузер: открытая панель на 390/430/768/1440 px без page-level overflow; ET/RU/EN заголовок формы и опция помощи с размером локализованы; ошибок/предупреждений консоли в проверенной сессии не было.
- Unit/integration: серверная схема отклоняет пустой размер на ET/RU/EN и принимает явную помощь с размером; eligibility принимает помощь, но не пустой цвет. Существующие тесты `service`/action покрывают успешное создание и повтор с тем же request key без второго Lead/уведомления.
- Финальный local gate: ESLint, strict TypeScript, Prisma validate с локальным заглушечным URL, 379/379 Vitest, production build — зелёные. Форматирование изменённых файлов и `git diff --check` — зелёные. Общий `prettier --check .` упирается в четыре ранее существовавших untracked audit-отчёта; они не менялись.
- Сквозная **реально сохранённая** синтетическая заявка не создавалась: локальная БД не была поднята, staging не выпускался. Это остаётся обязательным шагом перед P1 production release.

## Риски, rollback и согласование

P1 может увеличить число открытий формы и заявок, но эффект на подтверждённые покупки неизвестен. Размер всё ещё обязателен до отправки; форма не берёт оплату. Feature flag не добавлен: для этой небольшой правки он создал бы дополнительный постоянный код. P1 изолирован отдельным коммитом и не должен автоматически попасть в P0 release. Для P0-only релиза использовать только P0-коммит на отдельной ветке от текущей production-базы. После отдельного согласования P1 — staging E2E с одной удаляемой synthetic fixture, затем exact-SHA CI и отдельный production release. Откат P1 — предыдущий P0 SHA; никаких миграций P1 не требуется.

**P1 verdict: CONDITIONAL GO** — UX и локальные проверки готовы; staging E2E, согласование владельца и выпуск ещё требуются.
